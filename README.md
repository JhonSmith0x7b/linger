# Linger

macOS / Windows 桌面 AI 陪伴应用。Tauri 2 + React + Rust + SQLite，聊天与识别采用 OpenAI API，可配置局域网 NewAPI 中转；语音合成另支持阿里云 CosyVoice 和 MiniMax。

当前版本 **0.1.27**，处于实际试用阶段。**已知问题：Windows 悬浮窗的部分按钮在实际使用中仍可能无法点击，尚未修复。** 详情见[已知问题](docs/known-issues.md)。

[下载 Windows 安装包](https://github.com/JhonSmith0x7b/linger/releases/latest) · [构建与发布说明](docs/windows-build.md)

## 启动

需要 Node.js 22.12+、当前 stable Rust 和对应平台的 Tauri 开发依赖。macOS 需要 Xcode Command Line Tools，Windows 需要 MSVC C++ Build Tools 与 WebView2。

```sh
npm ci
npm run desktop
```

`desktop` 默认执行 `tauri dev`。本工作目录已有隔离 Rust 工具链时自动使用 `.cache/rustup` 和 `.cache/cargo`，不修改系统默认 Rust；其他机器使用 PATH 中的 Rust。

```sh
npm run build
cargo test --manifest-path src-tauri/Cargo.toml --locked
npm run desktop -- build
```

本机旧 Rust 环境下运行后端测试：

```sh
RUSTUP_HOME="$PWD/.cache/rustup" CARGO_HOME="$PWD/.cache/cargo" cargo test --manifest-path src-tauri/Cargo.toml --locked
```

## 初次使用

1. 在设置中填写自己的 Key。默认地址 `https://api.openai.com/v1`；中转地址填写包含 API 前缀的完整根路径，例如 `http://localhost:3000/v1`。
2. 各地址的 Key 分别存入系统凭据存储，不放 SQLite、日志或浏览器存储。切换地址后填写该地址的 Key。
3. 填写 Key 后点击“读取可用模型”，或者保存后自动读取；通过搜索和下拉列表选择各用途模型。默认 TTS 为 `gpt-4o-mini-tts`；语音合成模型与输出格式在角色卡中设置。模型列表反映当前地址和 Key 可见的模型，不保证模型支持每一种接口；中转别名会原样保留。
4. 观察默认使用主屏幕，可在开启陪伴的位置直接切换屏幕或窗口；设置中仍可配置区域与关注说明。macOS 首次截图／录音需在系统中授权。显式选择的屏幕与区域保留；窗口 ID 不跨重启复用，重启后回到主屏幕，界面显示当前来源。录屏失败会暂停观察并显示原因。
5. 按住 `CommandOrControl+Shift+Space` 或主界面录音按钮说话，松开提交；快捷键可在“陪伴与屏幕”中点击“录入快捷键”，直接按下组合键、松开后保存。录入时暂时停用原全局键，Esc、失焦或超时会取消并恢复原键。按下立即打断播报。单次录音最长两分钟。不足 300 毫秒的短按视为误触，不调用模型；正常按住但数字静音或转写为空时，角色会自然回应未听清，不伪造用户发言。麦克风、网络与 API 故障仍作为错误显示。
6. 点击主界面的「悬浮面板」或托盘菜单打开陪伴球：透明无边框，收起窗口为 96×56，包含陪伴球与常驻翻译按钮，靠近时显示翻译、对话和更多操作。单击打开文字输入，失焦收起并清空文字草稿；小球只负责点击打字和拖动，独立语音按钮点击开始、再次点击停止发送；颜色区分录音、转写、思考、播报与错误，读屏陪伴开启时有常驻青绿色光环，定时观察会短暂扩散动画。点击球旁「译」立即展开并聚焦输入，Enter 翻译、Shift+Enter 换行，底部大按钮复制译文；Esc 收起。翻译模型和目标语言在「设置 → API 与模型」配置（默认英语）；输入最多 4000 字符，可复制译文。翻译不附带聊天、记忆或截图，不自动播报、不保存译文。
6. 开启主动陪伴后按配置间隔观察（默认两分钟）；可暂停。关闭主窗口后应用仍驻留托盘，通过托盘打开或退出。可打开置顶悬浮说话窗口。
7. 在“角色卡”中选择凉宫春日、雪之下雪乃或峰不二子，或保留原有自定义角色。每张卡独立保存人格、音色 `voice`、声音 `instructions` 和语速 `speed`；可直接试听尚未保存的声音草稿，保存后整套配置用于后续对话。切换不清空聊天和记忆。主界面音量独立保存并即时生效，角色切换不会改变收听音量。插画只用于卡片和头像，不发送给对话模型。
8. 升级时自动将旧的全局音色、指令和语速迁移到当前角色，保留其他角色曾编辑的声音指令。迁移前原设置会在 SQLite 元数据 `settings_before_voice_profiles` 留一份备份；新配置不再保存重复的全局声音字段和覆盖开关。

## 已实现

- 定时观察明确作为无用户发言的后台事件：有新画面可自然交流，无新画面可延续话题或安静，不要求用户说话或打字。
- 原生录音 → ASR → Responses 流式文字／工具循环 → 分段 TTS → 原生顺序播放；过期轮次和语音取消。
- 截图工具、官方 web search、记忆新增／修改／删除、中文历史及记忆检索。
- 分钟级观察、画面指纹去重（相同画面不重新上传图片）、无需用户回复的交流／自语与静默选择。
- SQLite 聊天、设置、长期／今日／本次会话记忆；明确记忆立即写入；增量后台整理与版本冲突保护。
- 统一上下文预算：自动观察与用户对话均为最多 6,000 文本 tokens，共享相同的近期消息来源（包括主动发言）、记忆、摘要与关注信息。取消历史消息的提前字节截断，按总预算淘汰较早的完整消息。采用 o200k 本地估算并预留协议开销，图片另计，实际服务端计费可能不同。超限时裁去较早历史，当前输入不会静默截断；仍超限明确报错。
- 记忆整理条件：10 次用户输入、30 分钟且有新增用户输入、或约 4,000 tokens；失败至少五分钟后重试。没有每日费用预算或按余额自动降频。

## 当前实现边界与验证

已通过前端生产构建、91 项后端测试、模拟 Tauri 界面交互检查，以及 macOS `.app` 打包和真实界面启动／悬浮窗打开关闭验证。

- 本轮使用本地 HTTP 模拟服务验证 Responses、SSE、ASR multipart 和 TTS 参数；没有使用真实 Key 或产生付费调用。
- TTS 在完整回答返回后按句分段，由独立的有界队列连接生成与播放：播放当前段时最多提前生成下一段，按顺序播出；打断会清空待播音频并取消本地请求等待。尚未接入 WebSocket 或边生成回答边合成。文字增量会实时显示。
- 单次对话生成上限 4096 tokens，主动观察 2048，记忆整理 4096（包含推理 tokens，并非要求生成到上限）。回复长度按话题自然决定，不限制句数；不自动重试用户请求。高推理模型仍可能触及上限，错误按实际未完成原因区分。语义向量检索尚未启用。
- 区域当前通过像素坐标设置；还没有拖拽框选覆盖层。输入／输出设备可分别选择，默认跟随系统。
- 记忆保存明确内容和来源范围；历史可检索但不直接重新激活已删除／过期偏好。临时记忆到期会丢弃旧摘要以避免残留偏好。
- 当前播放支持 WAV、MP3、AAC、FLAC、PCM，未开放 Opus。TTS 模型退役后需要替换适配实现。
- Windows CI 已配置但未在本机运行；真实 Windows 按键、游戏全屏、权限、设备拔插、蓝牙、睡眠唤醒及局域网 NewAPI 兼容性仍需设备实测。自动观察不会积压补发任务。
- 不保存原始录音；截图历史默认保存发送给模型的压缩 JPEG，可在设置关闭或清空。聊天和记忆存入系统应用数据目录的 `linger.sqlite3`。本机数据库未加密。

## 代码导航

- `src/`：聊天、设置、记忆管理和悬浮界面。
- `src/characters.ts`：内置角色卡文本；`public/characters/`：随应用打包的静态插画。[生成提示词](docs/character-art.md)。
- `src-tauri/src/main.rs`：桌面入口、命令、快捷键、凭据与托盘。
- `src-tauri/src/session.rs`：会话取消、工具、上下文预算、主动观察、记忆整理。
- `src-tauri/src/api.rs`：OpenAI 协议与中转连接。
- `src-tauri/src/devices.rs`：原生录音、播放和截图。
- `src-tauri/src/store.rs`：SQLite 与记忆生命周期。
- `docs/`：产品共识和技术调研。`references/N.E.K.O` 仅供参考，不作为应用依赖。

聊天支持 Markdown（链接、列表、强调、代码与表格），链接在系统浏览器打开，外部图片不自动加载。TTS 单独提取可播报正文，过滤网址、引用标记、来源段落和代码块，原始聊天文本仍保留。

每次对话、播报完成或被打断后重新等待完整观察间隔，避免刚聊完又自动搭话；到期仍忙碌时每 5 秒检查，不积压任务。主界面与悬浮更多页显示本次运行的最近观察阶段及成功截图时间，区分等待、已截图、安静、已回复和失败。

音频输入与输出可在「设置 → 音频设备」分别选择，默认跟随系统。输入设备保存后重建常驻采集流，输出设备在下次播放生效；指定设备断开不会偷偷回退到其他麦克风。角色声音配置仍保存在角色卡中。

快捷翻译支持「设置 → API 与模型 → 翻译完成后自动复制到剪贴板」，默认关闭。开关立即保存生效，有效译文会自动替换剪贴板内容；修改原文后返回的旧结果不复制，失败时保留译文供手动复制。

悬浮面板收缩（失焦、Esc 或关闭按钮）清空翻译原文、译文和聊天输入草稿，不删除聊天记录。已提交的翻译可在收缩后完成自动复制，但不重新填回面板；输入新内容后旧结果失效。

### 试用阿里云声音

1. 在「设置 → 语音连接」选择服务、填写完整的合成接口地址并保存该地址的 Key，随后保存设置。
2. CosyVoice 北京地域接口为 `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api/v1/services/audio/tts/SpeechSynthesizer`，请替换业务空间 ID，并使用同地域的 Key。
3. MiniMax 使用阿里云接口 `https://dashscope.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation`，不是 MiniMax 自有平台的 Key 或接口。
4. 在角色卡选择对应服务、模型和音色，填写试听文本即可测试。各服务草稿分别保留，保存后用于对话播报。试听显示生成及下载耗时，不含播放时间。
5. 第一版阿里云声音使用非流式 MP3 / WAV。系统音色与自定义音色支持范围随模型不同；CosyVoice 3.5 需要已创建的复刻或设计音色。MiniMax 使用情绪、音高等参数，不支持 OpenAI 风格的自由声音指令。

接口依据：[CosyVoice HTTP API](https://help.aliyun.com/zh/model-studio/cosyvoice-tts-http-api)、[阿里云 MiniMax API](https://help.aliyun.com/zh/model-studio/minimax-synchronous-speech-synthesis-api)。支持在角色卡上传参考音频创建 CosyVoice 复刻音色；声音设计暂未接入，也可填写已有音色 ID。


0.1.8 增加 CosyVoice 参考语音上传：在角色卡选择 CosyVoice 模型后，选择本地 WAV / MP3 / M4A 文件，再点击“上传并创建音色”。音频直接发送到当前配置的阿里云语音服务，不需要公网文件地址；本地不保存原始样本。推荐清晰、单人、无背景音乐的 10–20 秒录音，文件最多 10 MB，时长 5–60 秒，采样率至少 16 kHz，WAV 使用 16-bit PCM。格式、时长和音质须满足服务要求，云端会继续校验。

创建后显示音色 ID 并查询处理状态，就绪后点击“使用这个音色”，试听满意再保存角色卡。复刻音色绑定创建时的模型，切换模型需要使用对应音色。最近一次创建返回的 ID 按连接地址和模型保存在本地，关闭面板或重启后可恢复查询；网络超时不会自动重复创建。选择文件本身不会上传，只有点击创建按钮才发送。MiniMax 和 OpenAI 暂不提供参考语音上传入口。


0.1.9 将 CosyVoice 内置龙安洋、龙安欢的系统音色指令改为下拉选择：按模型与音色显示情绪、场景、角色和身份，自动生成规定句式及标点；手动填写的龙安欢 V3 (`longanhuan_v3`) 在 v3-flash 下提供方言选择。复刻音色保留自然语言输入，其他手动填写的系统音色仍需按其官方说明输入。已有合法指令会还原为对应选择；不匹配的旧文本会保留并提示重新选择。无效的已知系统音色指令在合成请求前被拦截，不发送给云端。


0.1.10 增加音色名称和音色库：上传时填写中文名称，已有音色可在列表中重命名；名称仅保存在本机，阿里云音色 ID 不变。列表保留多条音色记录，展示所属模型及状态，可选择与当前模型匹配的音色用于角色卡。旧版保存的最近音色记录会保留，可通过刷新云端找回更多由 Linger 创建的音色（`linger` 前缀）；这不是账号全部音色数量统计。

删除按钮用于删除云端音色，确认前显示音色名称和 ID；删除不可撤销，正在被已保存角色声音方案使用的音色不能删除，当前界面尚未保存但已选中的音色也会禁用删除。不会自动清理云端音色，失败时保留本地记录。

根据[百炼声音复刻说明](https://help.aliyun.com/zh/model-studio/voice-cloning-user-guide)，账号自定义音色上限为 1,000 个，声音复刻与声音设计共用额度，不按模型分别计算；达到上限需删除不再使用的音色。当前该文档未说明固定到期时间或定期清理要求。


0.1.11 拖动悬浮球时立即收起对话预览，先缩小原生窗口再开始拖动，避免展开面板阻挡靠近屏幕边缘。拖动期间不因悬停或新消息重新展开，拖动结束后再次移动鼠标悬停可恢复预览；单击输入和双击打开主窗口保持原有行为。

### 0.1.23 按键录音

麦克风采集与单次发言分离：应用启动后准备已选输入设备，按键／录音按钮只控制音频是否进入本次录音。待命声音直接丢弃，不保留按键前预录音、不上传、不触发 ASR；系统会持续显示麦克风使用状态，退出应用释放设备。首次授权、设备切换或休眠恢复时可能需要准备时间，界面区分准备中、就绪、录音中和设备异常。正常发送时额外收集约 100 毫秒尾音，误触判断按实际按住时间计算；清空对话等丢弃操作立即停止收集。仍保留误触过滤和两分钟单次录音上限；设备中断的录音不会与恢复后的声音拼接。

验证应包括：就绪后立即开口的首字、连续两次录音不串音、准备中快速松开、输入设备切换／拔插、休眠恢复、两分钟上限。自动测试验证缓冲和状态逻辑，实际设备延迟仍需 macOS 与 Windows 分别验收。

### 0.1.24 Responses 流式兼容

聊天、翻译和后台记忆整理统一使用数组 `input` 与 `stream: true`，无需选择兼容格式。最终完成响应有完整 `output` 时优先使用；最终数组为空时，从按索引收集的完整 `response.output_item.done` 项恢复文字、搜索引用、函数调用和 reasoning 项。只有成功完成才能返回结果；失败、输出不完整或断流不会执行已收集的工具。

部分 Codex 中转接受但不执行 `max_output_tokens`，因此该参数不是此路径的输出或费用硬上限。本地仍执行 6000 token 文本输入预算。客户端为异常响应设置事件与整轮流量限制，达到限制将报错并停止本地读取，不将截断结果当作成功；这不保证上游立即停止生成或计费。

回归测试包含用户提供的人工对话／JPEG 兼容性实验中脱敏裁剪的 SSE 项目事件；没有真实聊天、截图、Key 或可用 reasoning 密文。离线回放验证协议适配，不等于已在官方或中转账号上重新发起实测；ASR、TTS 和模型列表仍需各自的对应接口支持。

0.1.25 修复 macOS CI 中 SSE 回放测试的 TCP 连接阻塞模式，恢复自动发布；应用功能与 0.1.24 一致。

### 0.1.26 历史互动与截图回看

角色定义固定；长期记忆包含用户档案、事实与明确反馈，不新增独立相处经验；近期摘要与活动简记仅衔接当前对话。临时要求不自动升级为长期偏好，当前纠正优先于旧摘要，用户档案不重复提取到普通记忆。

本地 `history.sqlite3` 与 `screenshots/` 将聊天、定时观察、截图和必要工具结果关联到互动编号。旧消息增量导入，仍可搜索。仅保存实际采集的压缩 JPEG；相同字节复用图片，但每次观察保留时间和来源。默认保留24小时，图片占用最多500 MiB，启动、定期及访问时清理。图片过期后保留标注不可用的附件记录与文字，不会假装能查看旧图。数据保存在本机应用数据目录，不加密。

最近消息提供轻量附件编号；最近观察和当前讨论画面分别定位，新的定时观察不覆盖讨论指针。`search_history` 返回最多5条文字候选，`read_history` 展开有上限的资料，`view_screenshot` 才向模型附带历史原图及其时间。每轮累计最多搜索2次、展开2次、历史图片2张、历史工具文字2000 token；当前6000 token文本上下文预算继续生效，图片输入消耗单独计算。搜索仍是字面关键词／时间／类型查询，未引入向量检索。

「陪伴与屏幕」可关闭保存（保存设置后清空旧图）或单独清空截图；聊天文字保留。清空对话会同时清空互动档案和截图，保留用户档案与长期记忆。后台没有每张截图额外生成描述的模型调用，复用已有活动简记。工具档案只保存必要摘要，不保存原始完整网页、音频或 reasoning 密文。

### 0.1.27 时间上下文

固定角色与通用规则保留在 `instructions`；历史消息带固定发送时间与类型。用户档案、记忆、摘要、截图索引及本轮时间放在历史之后、当前输入之前，以减少动态字段对历史前缀缓存的干扰。当前本机时间精确到分钟，包含日期、星期和 UTC 偏移；同一轮工具调用沿用时间基准。上次用户发言独立查询，不把自动观察当成用户回应。所有文字仍计入6000 token预算，裁剪只移除历史消息，保留本轮上下文与工具配对。实际缓存命中由服务端决定。
